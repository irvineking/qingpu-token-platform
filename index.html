01

项目定位

一句话讲清楚平台是什么

本质是 LLM API 聚合网关。 政务级计量结算与补贴发放通道不捆绑进每一户企业，而是作为可独立开通的政务能力选项。 底座让区内企业一个账号、一个 API Key 调用主流大模型，并通过智能路由把任务分给性价比更合适的模型； 若区里需要政策兑付与监管，再叠加计量结算与补贴通道，实现补贴精准投放、用量全程可审计。

03

四大核心功能模块

需求主体框架
MODULE 01 · 底座

统一 Token 接入与单点登录

  • 一个平台账号 → 自动获得统一 API Key / SDK / Web 控制台
  • 聚合国产合规模型：DeepSeek V3/R1、通义千问、豆包、智谱 GLM、文心、Kimi、MiniMax
  • 海外模型走合规通道：GPT-4o/o1、Claude 3.5/3.7、Gemini 2.0
  • 对接青浦本地智算节点与私有化开源模型实例
  • OpenAI 兼容协议，企业原代码改一行 base_url 即可切换
  • 企业子账号体系（多部门 / 多员工）+ 一网通办法人 SSO
MODULE 02 · 底座

智能路由与任务拆分

  • 静态路由：企业自行指定场景默认模型
  • 动态路由（核心卖点）：小模型做任务理解与复杂度评估 → 自动拆子任务 → 简单任务走便宜模型、复杂推理走强模型 → 结果聚合返回
  • 每笔请求的路由决策、token 消耗、节省金额对用户全程可见
  • 超时 / 限流 / 模型故障自动降级，业务不中断
MODULE 03 · 可选项

政务级计量结算 OPTION

  • 五维计量：企业 / 部门 / 员工 / API Key / 模型 / 时段
  • token 级精确计费（prompt + completion 分开），自动出日 / 月账单
  • 每一笔请求全留痕：调用方、时间、模型、输入输出摘要、费用、是否命中补贴
  • 敏感词过滤 + 异常调用告警（如小时级异常烧钱）
  • 三账户余额并行：现金余额 / 政府补贴额度 / 赠送额度
MODULE 04 · 可选项

补贴发放通道 OPTION

  • 政府后台按企业类型（高新 / 专精特新 / 规上 / 初创）配置差异化补贴额度
  • 按模型倾斜：用国产模型补贴比例高，引导信创
  • 企业在线提交资质 → 政府在线审核 → 自动发放补贴额度
  • 每笔消耗自动抵扣补贴，余额、已用、剩余全透明
  • 政府大屏：补贴发了多少、发给谁、用在什么场景、满意度如何
03B

建设与开通选项

底座必选，政务能力按需叠加
BASE · 必选

统一调度网关

所有租户默认开通。一个入口聚合授权模型，完成登录、路由、限流与基础用量展示。

  • 统一 API Key / SDK / 控制台，OpenAI 兼容协议
  • 国产合规模型 + 经评估后再开的合规出境通道
  • 可对接青浦本地智算节点与私有化实例
  • 智能路由：简单任务走便宜模型，复杂推理走强模型
  • 企业子账号与一网通办法人 SSO
OPTION A · 可选

政务级计量结算

面向需要审计、分摊和对公出账的国企、集团及区级监管场景。把每一次调用变成可复核的财政与企业账单。

  • 五维计量：企业 / 部门 / 员工 / API Key / 模型与时段
  • 输入、输出分开计价，缓存命中单独记账，价格版本不可回改
  • 三账户并行：现金余额 / 政府补贴额度 / 赠送额度
  • 日账单、月账单；平台计量、上游账单、企业确认三方对账
  • 对公转账、电子发票；补贴部分可单独出账、单独核销
  • 请求级留痕（调用方、模型、摘要、费用、是否命中补贴），日志留存 3 年
  • 异常烧钱告警、敏感词过滤，满足区级审计抽查
适合：区级监管驾驶舱、国企成本分摊、专票与部门预算。不开通时，企业仍可查看基础用量，但不具备政务口径对账与三账户账本。
OPTION B · 可选

补贴发放通道

把区里的算力或模型使用支持，从线下拨付改成「申报—审核—额度到账—调用抵扣—复盘」的在线通道。

  • 按企业类型配置额度：高新 / 专精特新 / 规上 / 初创等
  • 按模型倾斜：国产模型补贴比例更高，引导信创方向使用
  • 企业在线提交资质 → 主管部门在线审核 → 额度自动入账
  • 调用时自动抵扣补贴，现金与补贴分账，余额 / 已用 / 剩余透明
  • 可限定场景与模型白名单，避免补贴被用于无关调用
  • 政府大屏：发了多少、发给谁、用在什么场景、有无异常
依赖选项 A：没有可信的政务级计量，就不能做自动抵扣与审计复盘。不发区级补贴的项目可只开网关，或只开网关 + 计量。

组合 1 · 企业调度版

只开通统一调度网关。区内企业一个账号调用模型、看基础账单，政府侧不做补贴兑付。

底座　　适合先验证接入与降本

组合 2 · 治理结算版

网关 + 政务级计量结算。满足国企分摊、对公开票、用量审计，但暂不运行补贴政策。

底座 + 选项 A

组合 3 · 政策兑付版

在计量账本之上开通补贴发放通道，形成「政策—申报—抵扣—监管」闭环。

底座 + 选项 A + 选项 B

06

政府立项必补能力

评审时一定会被追问的硬指标
数据安全与合规

数据默认不留存、可配置存储；部署青浦政务云，数据不出上海；等保 2.0 三级。

国密与加密

支持 SM2 / SM4 国密算法，与上游模型间全链路加密。

信创适配

兼容昇腾 / 海光 / 寒武纪芯片，麒麟 / 统信 OS，争取上海市信创试点。

政务驾驶舱

全区用量大盘、企业活跃度、模型 TOP 榜、补贴进度、异常告警可视化大屏。

政务系统对接

预留一网通办、法人库、信用平台、企业服务平台对接接口。

SLA 与财务闭环

可用性 ≥99.9%；支持对公转账、电子发票自动开具、补贴部分单独出账。

选项开通前需确认

  1. 首期开哪一档？建议种子阶段先上企业调度版，有明确区级补贴文件后再开政策兑付版，避免账本与政策规则一并试错。
  2. 计量结算的出资与出账主体？企业现金消费与财政补贴必须分账，发票税目与补贴资金渠道要在合同和财政口径里先写死。
  3. 补贴审核权限落在哪？区科委、经信或大数据中心的审核流、额度变更与追回规则，需要书面授权后再接系统。
  4. 境外模型是否进入可补贴范围？建议补贴白名单默认仅国产授权模型；境外通道即使底座可接，也不进入补贴抵扣。
